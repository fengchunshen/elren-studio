### 本轮验证结果

- 前端全量：22 文件、72 测试通过（单 worker，包含保存、模板、分组、平台 UI、Prompt 和字幕）；随后新增视频控件专项 1 文件、2 测试通过；高级集成入口补充后，菜单与 UI 治理专项 2 文件、6 测试通过（与全量有重叠，不累加）。前一轮并发测试出现 UI 超时，未作为通过证据。
- 后端全量：33 测试通过、1 跳过；包含实际 FFmpeg 测试，供应商使用模拟响应。
- 最终生产构建通过，单文件 3.13 MB（gzip 1.08 MB）；`git diff --check` 通过。
- Chrome：复用现有 `localhost:8081`，创建独立“组件收敛验收 2026-09-09”项目；没有清空原核对项目。执行了引用、指令、多源连接、刷新、裁剪和文字素材复用。
- 文件上传：扩展 `fileChooser.setFiles` 返回 `Not allowed`，因此音频／视频／GLB 上传、视频目标编辑及完整时间线不能算 Chrome 已通过。未绕过权限。

### 仍需外部条件或进一步验收

1. 真实模型账号、当前允许的供应商请求／输出协议、正式价格与费用核对。`video_edit_contract: 1` 是内部合约声明，不等于接入某家供应商；未确认映射的模型保持不可执行。
2. Seedance 合规验证没有可用协议；未造入口或成功提示。全景／场景类型和公共 AI 角色数据源也没有据此虚构。
3. Chrome 文件权限恢复后继续视频／音频／GLB、完整时间线和字幕出口验收；主体与角色管理、标注到对话、其余主题和全部历史复杂节点仍需专项实机复验。
4. 节点呈现收敛并非全部旧类型重写：旧项目、模板、运行状态和素材继续保留，不能据此宣称 31 类都已经达到同等成熟度。

本轮未提交 Git、未部署、未迁移生产数据库、未开放模型或发布价格。

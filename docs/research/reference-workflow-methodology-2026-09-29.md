# 从 Tapnow 实际画布提炼的制作方法

2026-09-29（用户时区）。复用系统 Chrome 的现有 Tapnow 登录，查看模板只读预览、应用详情；未克隆其项目、未提交生成或安装应用。以下是观察到的组织方法及 Elren 适配，不复制作品、素材或原文提示词。

## 观察证据

模板预览足以证明节点组织和连线，不证明其模型执行或成片质量。主页部分视频显示加载失败，未据此评价作品质量；角色一致性等宣传不能作为已验证能力。

## Elren 的可执行方法

1. 写实际剧本：人物目标、场景、动作、对白、声音和结尾，不把写作指令放进文本节点当作完成。
2. 建共享人物/场景约束，分别建立定妆与场景图节点；文生图或图片编辑按后台实际能力选择。缺参考时保留图和连线并报告阻塞。
3. 将剧本、设定和图片真实连入图片分镜板；逐镜写景别、机位、构图和人物关系。
4. 每镜确认图片后，视频分镜用 `imageSource.nodeId + shotId` 读取对应画面，写动作、运镜、节奏和声音。未确认或断线时阻止误执行。
5. 选定视频后接入现有剪辑时间线，按稳定镜头身份去重，保留手工裁切。声音、字幕、混音按现有能力交接，不冒充完整多轨后期。
6. 修改只针对受影响镜头；上游改稿不会自动重写既有分镜或静默替换已剪片段。

## 同步实现

- `src/lib/agent-workflow-library.js`：三类可复用方法、实际节点端口、原创短剧蓝图。公共模板和助手读取同一蓝图。
- `read_workflow_library`：让助手获取方法和组件契约。
- `apply_workflow`：原生结构化对象，批内 key 前向引用、版本检查、端口/容量校验、命名分组、按节点尺寸布局；原子保存与撤销，不执行模型。
- `inspect_workflow`：分别报告结构错误与缺模型/素材/未确认画面的阻塞；检查孤立节点、循环、失效来源和视频分镜绑定。
- 分镜的真实执行读取逐镜模型与规格，创建和板级模型同步均写入各镜；检查工具也校验逐镜模型。对白与声音在选中镜头内可编辑，并实际拼入视频提示词，不能只存为不可见元数据。
- 保留已有文字、图片和视频工具；补充分镜/时间线的工作流操作。复杂分镜逐镜执行仍通过现有节点界面。

真实助手首次创建大图时暴露了 JSON 字符串转义错误；已改为原生对象并保留旧操作日志的兼容解析。原子图输出包含镜头和边，模型输出上限由4096调整到8192；轮次上限仍为32。固定千像素列宽也导致全景超出视口，改为列内最大宽度加间隔，纵向按节点高度排布。

自动测试覆盖前向引用、模型阶段匹配、绑定/确认门槛、时间线选片与裁切、幂等重放、原子拒绝、旧素材保留和布局复用。浏览器使用普通 creator 和现有8081服务；真实媒体生成、人物一致性、完整60–90秒成片与声音字幕不在本轮验收范围。

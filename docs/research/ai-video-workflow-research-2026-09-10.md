# AI 视频制作流程调研与 Elren / 参考产品对照

调研日期：2026-09-10。用途：先明确创作流程，再决定产品补齐顺序和模型采购。文字主模型保留用户已确定的 DeepSeek V4 Flash；国内配音优先评估豆包语音 2.0，尚未做试听选型。

## 1. 结论与证据范围

本轮查阅参考产品的画布、Agent、主体、生成、播放列表文档，Runway 的制作指南及 API 工作流，Adobe 的分镜和剪辑教程，以及导演对具体 AI 短片的制作自述。另检查本仓库当前输入、对话、时间线和渲染代码。

这些来源支持一种反复出现的制作方式：确定交付要求，建立参考标准，规划镜头，生成候选，选择可用片段，在时间线上修改并完成声音和包装。它不是行业占比调查；不能据此声称所有团队使用同一工具、同一模型或固定步骤。厂商教程说明可执行方法，导演自述说明个人实践，都不是本项目的质量实测。

核心判断：Elren 应围绕“镜头如何从要求变成可交付片段”组织工作，画布负责探索与引用，镜头清单负责进度和版本，时间线负责节奏与成片。已有一键流程可以作为入口，但正式制作仍需要可以定位、替换和保留结果的中间产物。

Runway 的长片指南从叙事和参考设计出发，将生成片段交给剪辑软件装配；Adobe 的教程则演示从已有素材粗剪出发，在剪辑过程中生成缺失镜头，并混合声音。两种起点都成立。[Runway 制作指南](https://help.runwayml.com/hc/en-us/articles/26871350018835-How-to-create-longer-videos-and-films)、[Adobe 浏览器剪辑教程，2026-08-07](https://www.adobe.com/learn/firefly/web/edit-videos-with-ai)

## 2. 建议作为产品基础的制作主线

下表是结合来源形成的本项目工作流建议，各环节可回退；确认点是创作者可用的检查机制，并非要求每一步都弹窗审批。

| 环节 | 实际要做的事 | 应留下的产物 | 进入下一步前检查 |
| --- | --- | --- | --- |
| 需求与资料 | 明确受众、用途、时长、比例、卖点、已有素材和必须保留的信息 | Brief、参考资料、交付规格 | 做给谁看、要传达什么、哪些事实不能改 |
| 创意与脚本 | 选择叙事方向，写镜头内容、旁白或对白 | 可编辑脚本、初步镜头表 | 内容能否在时长内讲清，声音路线是否确定 |
| 角色/产品/场景标准 | 汇集产品实拍、多角度人物、服装、道具、环境和风格参考 | 可复用主体及参考版本 | 身份、包装、服装、空间是否一致 |
| 分镜与节奏预演 | 确定景别、动作、机位、镜头用途；把静帧按预计时长排列并加临时声音 | 分镜图、带时间的样片（animatic） | 顺序、视线、动作衔接、旁白长度是否合理 |
| 镜头生成 | 逐镜头或按短场景生成；选择图生、首尾帧、多参考或视频编辑 | 同一镜头的多个候选版本 | 运动是否成立、主体有无变化、有声输出是否可用 |
| 挑选与局部修改 | 选择候选的可用区间；只重做有问题的部分 | 选用版本、入出点、修改原因 | 已确认镜头是否保留，替换是否影响邻接镜头 |
| 粗剪与声音 | 排镜头、调整长度；安排对白、旁白、音乐、音效 | 可连续播放的剪辑序列 | 全片节奏、断声、口型、音乐遮挡对白等 |
| 精修与交付 | 字幕、标题、品牌包装、调色、必要的增强和多比例输出 | 成片、字幕、素材及版本清单 | 下载后的文件与预览一致，内容和规格均正确 |

Adobe 的分镜教学强调使用参考图保持风格和人物一致，再把确定的画面转成动态镜头。项目据此应把参考确认和镜头预演放在大量视频生成之前，但允许已有素材直接进入剪辑。[Adobe 商业分镜教程，2026-06-25](https://www.adobe.com/learn/firefly/web/create-commercial-storyboard-firefly-boards)

参考不是每镜头都机械上传相同九宫格。应按镜头选用相应视角与用途，区分主体标准、构图参考、动作参考和灯光参考。分镜图表达计划，生成首帧表达具体起始画面，二者可以相同，也可以分别制作。

## 3. 五类视频的顺序不同

| 场景 | 实用路线 | 对采购和产品的影响 |
| --- | --- | --- |
| 产品广告、品牌短片 | 产品资料 → 创意/旁白草稿 → 主视觉与分镜 → 视频候选 → 剪辑包装 | 图片编辑和产品一致性优先；品牌字标可在后期叠加，不必让模型重画 |
| 角色短剧、剧情片 | 剧本 → 角色/场景/道具标准 → 场景与镜头 → 对白/表演路线 → 生成 → 反应镜头与剪辑 | 固定角色声线、多人关系、镜头连续性、版本管理更重要 |
| 数字人口播 | 文案 → 音色和实际语音 → 人像/角色 → 音频驱动视频 → 字幕与插入镜头 | TTS 不会自动产生对口型画面，须有音频驱动/口型或数字人能力 |
| MV、音乐卡点 | 已选音乐 → 段落/节拍 → 视觉方向 → 镜头 → 卡点剪辑 | 音乐在前；歌曲已存在时无需重新采购音乐生成 |
| 实拍/存量素材改造 | 导入素材 → 转写/镜头分析 → 粗剪 → AI 补镜头或局部编辑 → 后期 | 分析、素材检索、编辑回填优先，不强制全部经过文生图 |

声音至少有三条生产路线：视频模型原生音画同生；已确定对白或演出驱动人物；画面生成后独立配旁白、音乐和音效。它们可以混用。对于要逐字准确且保持角色声线的对白，应先验证声音和口型路线，不能先把整部片生成完再靠配音补救。

Runway 的多角色对话教程明确先录制表演/对白，再依照实际时长制作基础画面并驱动角色。这证明“声音先做”是一条真实路线，不意味着所有对白都必须采用该产品。[Runway 对话场景教程](https://help.runwayml.com/hc/en-us/articles/41748090660499-Creating-Multi-Character-Dialogues-with-Act-Two)

## 4. 当前视频生成也不只一种方法

| 方法 | 优先使用条件 | 不能保证的事情 |
| --- | --- | --- |
| 纯文字生视频 | 探索气氛、概念、通用补充画面，尚无精确参考 | 不保证跨镜头角色、产品和空间恒定 |
| 单图生视频 | 开场构图已确认，要控制该镜头如何开始 | 不自动保证结尾落点 |
| 首尾帧 | 确实要求特定开头和结尾，且动作能连接 | 两张图并非任意组合都能自然过渡，不必每镜头强加尾帧 |
| 多模态参考 | 用人物/产品图、动作视频、音频等分别约束内容 | 接受音频参考不等于严格口型同步；不同模式上限不同 |
| 多镜头生成 | 探索一个短场景的连续镜头和表演 | 不替代最终剪辑，也不保证每个内部镜头都可用 |
| 视频编辑/重拍/延长 | 已有可用运动或画面，问题可以被局部描述 | 保留范围和支持时长需实测；重生成会产生变化 |

Runway 的 Seedance 教程区分参考、首尾帧、纯文字三种模式，并给出分镜驱动、换角色和改风格示例。参考产品当前也提供 Frames、Omni Reference、Video Edit 等模式。产品必须按任务组织输入，不能只是统一展示一组模型名。[Runway Seedance 指南](https://help.runwayml.com/hc/en-us/articles/50488490233363-Creating-with-Seedance-2-0)

低价模式适合试构图或动作，但切换模型或模式后并不保证复现原候选。如果支持对既有结果做保真增强，可单独评估；否则应告诉创作者这是重新生成，需要再选择一次。

## 5. 从真实制作案例能学到什么

导演 Kévin Mendiboure 在 2026-06-09 的 CATACOMBES 访谈中说明，他先做人物、场景和道具参考，再规划镜头及首帧；人物受伤后还要更新对应参考。他用较低质量模式探索，再选择正式候选，也会因生成结果调整镜头计划。这是一个个人案例，不能把其尝试次数、耗时或成功率当作我们的预算参数。[导演访谈](https://www.creativebloq.com/ai/how-a-filmmaker-turned-a-10-year-old-unmakeable-movie-idea-into-reality-with-ai)

对本项目的推论：参考需要版本，镜头需要多个候选和可用区间；“角色 A”在不同剧情阶段可能是不同外观状态。只保存一张角色图、一个最新视频 URL，不足以支持长流程修改。

同时，一键方案确实存在：Runway 的 Product Ad Recipe 从产品照片及创意要求生成广告结果。但这属于已封装的特定工作流；是否向用户开放中间分镜、如何局部改稿，是产品层面需要另行验证的能力。[Runway Product Ad Recipe](https://docs.dev.runwayml.com/recipes/product-ad/)

## 6. 参考产品值得借鉴的组织方式

| 参考产品已公开的方式 | 在制作中的价值 | Elren 应吸收什么 |
| --- | --- | --- |
| 画布保存输入和派生结果，连线表达来源关系 | 从成片问题回到相关素材 | 画布与镜头/时间线之间可定位，不把连线误当自动执行 |
| 主体组合图片、视频、音频和文字参考 | 重复使用同一角色或产品 | 保留资源身份、用途、版本及模型可消费的输入 |
| Agent 读取 Brief、制定步骤、调用工具、定向修改 | 降低跨环节操作成本 | 能执行编辑与生成操作的 Agent，普通聊天只是基础 |
| 自动生成与手动确认两种方式 | 兼顾探索与连续批量制作 | 用户可控制范围、数量和消耗，不强迫每步确认 |
| 视频结果可剪辑、截帧、编辑、延长、重拍 | 利用已有合格素材修改 | 定向修正而非无差别重跑整个项目 |
| 播放列表按入出点排列并合并视频 | 检查完整叙事和衔接 | 成片预览与下载后复核，原片保留 |

以上依据参考产品的公开文档，只说明产品行为，不披露其后台实际采购或编排实现。

参考产品播放列表文档明确图片和音频不能直接作为视频片段加入；该文档覆盖排列、裁切、切分和合并，没有证明专业多轨混音、字幕包装和调色全部可在该入口完成。我们的目标应按交付需要补齐，不能因为菜单相似就认定成片能力足够。

另外，参考产品的 3D 片场可以用于站位、机位和取景；预览、拍摄、进入片场本身不调用生成模型。空间预演有价值，但与采购 3D 生成模型是两回事。

以下为本轮源码与现有实施记录核对，不是本轮浏览器验收。历史 09-08 缺口已有部分修复，不沿用旧清单把它们重新标为缺失。

| 能力 | 当前证据 | 对流程的影响与建议 |
| --- | --- | --- |
| 参考与素材 | 已有主体、内联引用和内容快照，实施记录有部分浏览器验证 | 继续补实际供应商输入验收；无需重建一套主体入口 |

| 时间线 | 已有视频排序、裁切、连续预览及后台 FFmpeg 合并 | 基础存在，需完成真实视频导入到导出的验收 |
| 静帧预演与声音合成 | 后端 `validate_clips` 只接受视频；片段只允许资产 ID、入点、出点 | 目前不能直接把分镜静帧、旁白、配乐、音效和字幕一起合成；这是优先补齐项 |
| 视频理解 | 普通聊天对非 Gemini 视频仅加入文件名占位文字 | 换成 DeepSeek 后不能称视频已被理解；需要抽帧/时间戳/转写，或专门的视频理解输入 |
| 创作 Agent | 当前 Chat 适配发送 messages 并读取文本结果，本轮未发现工具调用执行循环 | DeepSeek 支持工具调用不等于项目拥有创作 Agent；需实现操作、任务等待、结果回填和定向修改 |
| 视频专用编辑 | 已有框选/分段/延长的内部合约与测试记录 | 按所选供应商映射并验收；不能以内部字段存在代替实际模型能力 |
| 费用与任务恢复 | 已有后台任务、价格快照、用量结构 | 在现有结构上按镜头归集生成、重试、编辑、声音和导出费用 |

## 8. 应当如何调整采购

先区分“交付必须有声音”和“必须购买声音生成”。声音可以来自实录、授权素材、视频原生音轨或独立模型；字幕和时间线也不等于一个新的生成模型。

| 项目 | 本轮建议 | 采购触发条件 |
| --- | --- | --- |
| DeepSeek V4 Flash | 保持用户选定，负责文字、规划和结构化要求 | 基础接入 |
| 视觉/视频分析 | 独立能力，尽早用实际素材验收 | 要识图、分析参考视频或自动检查画面时；不得将纯文字模型视为已覆盖 |
| Seedream 5.0 Pro | 主图片生成与编辑方案 | 产品/角色/分镜路线的基础；原生组图另评估 Lite |
| Seedance 2.5 | 主视频方案，测试首帧、多参考、原生声音和编辑 | 基础视频路线；逐项确认模式而非只验证模型名 |
| 豆包语音 2.0 | 国内独立旁白与对白方案 | 要准确文案、固定声线、独立可混音音轨时 |
| 音乐生成 Mureka | 从“所有任务必买”改为按任务启用 | 需要原创歌曲/配乐，且现有素材不能满足时 |
| 可灵音效 | 国产模型候选，国内 API 地域和价格仍须核验 | 需要独立生成音效、原生视频音轨和素材库不足时 |
| Nano Banana Pro / 低价视频档 | 补充效果或试错策略 | 用同一组真实镜头证明改善质量/成本后再扩大额度 |
| 数字人/表演驱动 | 明确口播、角色表演路线后采购 | 单独 TTS 无法解决口型和肢体表现 |
| Topaz / 3D 生成 / 更多视频家族 | 维持按需追加 | 具体交付出现明确缺口 |

本轮没有重新比较各家模型的绝对质量，也没有根据厂商示例替用户作最终质量验收。具体模型协议和国内音频来源见[采购文档](../models/model-procurement-2026-09-10.md)。

## 9. 建议先跑通的 30 秒广告样片

这是本项目建议的验收设计，不是参考产品模板，也不是已生成作品。默认使用已有香水示例的业务类型，正式素材由用户选择。

| 镜头 | 成片计划时长 | 内容用途 | 制作方式建议 |
| --- | --- | --- | --- |
| 01 | 3 秒 | 建立场景和情绪 | 实拍或生成环境镜头 |
| 02 | 5 秒 | 产品首次清晰出现 | 使用确认产品图生成，检查瓶身和标签 |
| 03 | 5 秒 | 材质与细节 | 产品局部参考，轻微运动 |
| 04 | 7 秒 | 使用场景或人物动作 | 人物/产品多参考；难动作单独试拍 |
| 05 | 6 秒 | 主视觉收束 | 选用稳定镜头，检查与上一镜的衔接 |
| 06 | 4 秒 | 品牌及行动指引 | 静态/轻动背景，加独立文字与标志 |

总计 30 秒。这些是剪辑采用时长，供应商实际生成时长另按 API 档位选择；生成片段可以更长，最终只用合适区间。

先用六张分镜图加临时旁白/音乐排出 30 秒样片。只对已确认的镜头生成动态候选；记录选用理由和实际消耗。最终把旁白、原生环境音、额外音效及音乐分别安排，再做字幕和品牌包装。

实际验收至少包含一次“仅修改镜头 03”：其他镜头和声音保留；新候选可对比；时间线使用正确版本；刷新后恢复；下载文件逐帧与逐段听看检查。生成、修改、合并的错误应保留可追溯状态，不能靠重跑全片掩盖。

成本按实际记录汇总：全部候选生成费用＋局部编辑/重生成费用＋独立声音费用＋素材/渲染费用。观察“每个最终采用镜头的总成本”和“每秒最终交付视频的总成本”；不把模型标价乘成片时长当真实制作成本，不预设行业统一通过率。

## 10. 产品推进顺序

1. 先完成“产品资料→分镜静帧→带声音的节奏预演→动态镜头→成片”的一条链路，复用已有画布、主体、分镜和任务。
2. 补成片最小能力：静帧时长、独立音轨、字幕/品牌叠加、连续预览与导出。专业后期可以先对接外部剪辑工具，保留按镜头命名的素材、音轨、字幕及清单；不要宣称普通 ZIP 已是可重建工程。
3. 将已有选择/锁定扩展为镜头版本和定向返工。任务后台运行，离开页面后可恢复；不要为全自动而强制重跑已确认镜头。
4. 再让 Agent 操作这些已可验证的能力。先支持创建/改写镜头、选择参考、提交任务、等待、回填、替换时间线片段等动作，再组合模板。
5. 用同一套素材验证产品广告、角色短剧、口播等不同路线，按出现的具体缺口追加模型。

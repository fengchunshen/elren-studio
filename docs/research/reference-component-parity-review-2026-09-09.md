# 参考产品组件复核：遗漏、重复拆分与入口收敛

复核日期：2026-09-09（用户时区）。依据：当前已登录的系统 Chrome、参考产品官方现行文档、Elren 当前源码。本文是审查结论与调整建议，未执行节点删除或迁移。

## 结论

当前同时存在能力缺口和节点过度拆分。31 是 Elren 的内部节点类型数量，不是与参考产品等价的 31 项成熟能力。上一轮增加了基础编辑能力和平台 operation，但专用交互、输入契约及真实供应商执行尚未全部补齐；不能将这些范围仅归结为“等密钥”。

对齐目标应是：少数统一内容节点、上下文工具、可复用素材／主体及场景模板。保留兼容旧项目的内部 type，不要求把这些 type 全部暴露在用户的新增菜单中。

| 优先级 | 缺口 | 当前 Elren 实际情况 | 应补成什么 |
| --- | --- | --- | --- |

上述图片、视频选区和机位、时间线、主体引用、3D 和文字工具差距均对照参考产品的官方说明。这些是具体能力差距，不是建议把每行再增加成一个节点。

补充边界：官方明确文档／表格可作为 Agent 对话附件；当前全局菜单并未列“文档节点”，不能凭附件支持新增一个所谓缺失的基础节点。

## 建议的最终入口组织

- 核心新增：文本、图片、视频、音频、3D。
- 独立辅助：剪辑时间线、图片编辑器、3D 片场。
- 上下文派生：增强、数字人、图片编辑动作、视频编辑动作；执行后保留源内容并得到明确类型的结果。
- 素材管理：个人／团队素材、主体、AI 角色；直接进入参考输入。
- 扩展创作：智能分镜、脚本提取、视频拆解、图像对比等保留价值，按业务场景组织。
- 导出：下载、批量下载、保存素材放操作区；可选自动归档留给高级集成。

后续实施顺序：先修 P0 数据契约和专用交互，再收敛公共入口，最后迁移旧节点呈现。旧项目、模板 ID、连线、任务状态和用户素材必须可恢复，不能为了让菜单数字变小而直接删除内部类型。

本轮未修改业务源码、未提交 Git、未部署；本文件不表示上述建议已实施。

# Elren 画布 Agent Harness：首轮运行验证

日期：2026-09-23。前置调研：[方案比较](./canvas-agent-harness-comparison-2026-09-23.md)。

## 结论

**DeepSeek Harness 和 Deep Agents 都能完成此次真实模型的连续画布操作。DSH 核心也能通过适配层完成恢复和运行中追加指令，不必先采用 LangGraph。** 但当前本地 DSH SDK 不能原样承担所测试的跨进程恢复；它与 DSH 核心能力需要区分。

若继续做 Elren 原型，建议先采用 **DSH 核心 + Elren 专用适配层 + 现有生成任务服务**，理由是已有 Siran 代码基础，恢复/steer 接入可行性已运行验证。Deep Agents 保留为 Python 内集成的对照和备选；本轮它的现成检查点/暂停恢复接入更直接。

这不是最终生产选型，也不是通用智能排行榜。真实模型只有四组有效流程；多模态、长上下文、实际画布 UI 和并发生产条件均尚未验收。

## 实际执行范围

- 使用 Elren 数据库中当前配置的 `DeepSeek Flash`，上游模型标识为 **`deepseek-flash`**，渠道地址 `https://api.deepseek.com/chat/completions`。只读配置，密钥由现有函数在网关内存解密，没有记录到文件、日志或传给 Harness 子进程。
- 两边真实模型均为 `thinking=disabled`、`temperature=0`、每次最多 2048 输出 Token。DSH 子进程内部的路由标签为 `deepseek-v4-flash`，网关统一向已配置的真实上游发送 `deepseek-flash`，没有把两种模型混作对跑。
- Deep Agents **0.7.18**、LangGraph **1.2.12**、SQLite Checkpointer **3.1.1**、Python **3.14.3**。依赖装入独立临时环境。
- DSH 使用本地 Siran checkout，包版本 **0.1.6-alpha.1**、HEAD `fcfcc7ef87952270dd9553f6f6e27ddb1248bec8`。checkout 还有既有未提交修改，不能把观察外推为同版本所有上游安装的表现。实际构建文件 SHA256 见元数据；没有修改或重建 Siran。
- 同一合成画布：三个同名节点、独立 ID、明确选中顺序、原比例、提示词版本、同一参考素材身份。
- 所有创作工具只写实验 SQLite。图片/视频生成均为模拟任务，没有真实媒体生成、产品代码接入或业务数据库写入。

## 真实模型连续操作

每组包含三轮用户指令，两套 Harness 各重复两组：

1. 三个节点同名，只将选中顺序中的第二张改为 9:16、冷色背景，保留银色水杯及参考图，不生成。
2. 为刚才修改的那张生成一次，其他两张不动。
3. 查询刚才任务的状态，不重新生成。

| 结果 | 原 DSH SDK | Deep Agents |
| --- | --- | --- |
| 正确定位第二张而非同名第一张 | 2/2 | 2/2 |
| 只修改目标节点、保留参考身份 | 2/2 | 2/2 |
| 第一轮遵守不生成 | 2/2 | 2/2 |
| 第二轮只生成一次 | 2/2 | 2/2 |
| 第三轮引用已有任务并只查询 | 2/2 | 2/2 |
| 完整三轮流程 | 2/2 | 2/2 |

Deep Agents 的第一组曾把编辑动作 ID 用于生成，被共享领域服务以 `ACTION_CONFLICT` 拒绝；模型随后换用生成动作 ID 成功。这个例子说明业务幂等约束仍必须由工具实现，不能依赖模型总是选对 ID。没有重复生成。

证据：[逐项判定](../../experiments/canvas-agent-bench/results/2026-09-23/evaluation.json)、[DSH 第一组](../../experiments/canvas-agent-bench/results/2026-09-23/dsh-live-1/result.json)、[Deep Agents 第一组](../../experiments/canvas-agent-bench/results/2026-09-23/deepagents-live-1/result.json)。

## 故障与恢复：执行真实 Harness，模型决策使用固定夹具

下表测试的是状态/执行机制。固定夹具负责给出工具调用，因此不能用这些通过数评价模型推理能力。

| 场景 | 原 DSH SDK + 检查点 | DSH 核心 + 实验适配层 | Deep Agents + SQLite 检查点 |
| --- | --- | --- | --- |
| 读取、编辑、提交、查询链路 | 通过 | 通过 | 通过 |
| 手动修改后拒绝过期补丁 | 通过 | 通过 | 通过 |
| 正常关闭后新进程继续同一会话 | 失败：会话已存在 | 通过，保留原上下文 | 通过，保留原上下文 |
| 任务提交后丢回执，强制杀进程再恢复 | SDK 无法重开会话 | 通过，共享服务中仍只有一条任务 | 通过，共享服务中仍只有一条任务 |
| 工具执行中追加指令 | 收到，但排到原轮结束后 | 下一次模型请求即可见 | 本轮未测试直接 steer |
| 提交前暂停，新进程确认再执行 | 未测试 | 未测试 | 通过，确认前没有任务 |

### DSH 原 SDK 的问题定位

正常停止后再次向同一个 `canvas-session` 发消息，得到 `session "canvas-session" already exists`。对应源码 `packages/sdk/server/src/server.ts` 的 `createSession()` 使用 `ctx.agents.create()`，没有在此路径选择 `resume()`。

发送运行中新消息则使用 `agent.followup()`。其核心语义是 `next-turn`；`agent.steer()` 才是 `next-step`。实验中，新指令到第四次模型请求才可见，前三次已经完成原轮。因此不能把 SDK 的可排队发送称为已支持当前轮 steer。

DSH 最小配置还需显式挂载 `session-checkpoint-policy`。没有该策略的校准测试中，提交任务后立即杀进程，可能因记录尚未刷入持久存储而丢失上下文。挂载后日志保住，但原 SDK 的重开问题更明确地暴露为“已存在”。最终对比使用了检查点配置。

### 实验适配层验证

在 Elren 的实验目录编写 [dsh_bridge.mjs](../../experiments/canvas-agent-bench/dsh_bridge.mjs)，复用原 DSH 核心，未修改 Siran：

- 已有持久会话调用 `ctx.agents.resume()`，不存在时才创建。
- 普通消息使用 `followup()`；运行中追加明确走 `steer()`。
- 保留原事件流，并复用官方持久化与 checkpoint 插件。
- 通过能力握手确认真正加载了实验插件，避免配置未生效而误判。

最终五条模拟回归全部通过。强制中断后恢复能保留原始指令，并通过稳定 action ID 找回同一模拟任务；steer 从排到下一轮改善为下一次模型请求即可见。[中断恢复记录](../../experiments/canvas-agent-bench/results/2026-09-23/dsh-bridge-crash/result.json)、[steer 记录](../../experiments/canvas-agent-bench/results/2026-09-23/dsh-bridge-steer/model.json)

该适配层仅证明接入可行：单合成项目、文本输入、stdio，无多租户认证/调度、完整协议版本策略或真实媒体附件处理，不是可直接上线的 API。尚未实现和验收单独 cancel 入口。

## 用量与可比性

| 有效真实流程合计（每边两组） | DSH 裁剪配置 | Deep Agents 默认外围能力 |
| --- | --- | --- |
| 模型请求数 | 14 | 15 |
| 输入 Token | 15,477 | 55,900 |
| 输出 Token | 756 | 1,085 |
| 缓存命中输入 Token | 12,669 | 50,176 |
| 单组三轮墙钟耗时 | 7.505 / 6.972 秒 | 9.261 / 7.215 秒 |
| 模型可见工具数 | 5 | 13 |

不能据此宣称 DSH 固有地更省或更快。DSH 只暴露领域工具；Deep Agents 还包含默认虚拟文件与 general-purpose 子任务工具，系统提示更大。本轮模型没有调用这些额外工具，后续应先按产品需求裁剪，再做成本对比。执行顺序、缓存、预热和极小样本也影响耗时。

两边通过同一网关访问模型，网关先读取上游非流式响应，再将结果转为 DSH 所需 SSE；故这些耗时不代表真实逐 Token 流式体验。媒体输入只有身份和文字描述，没有向模型传真实图片。

包含校准失败的全部真实调用为 **35 次，输入 75,575 Token、输出 2,067 Token，缓存命中输入 65,405 Token**。这是供应商响应中的用量，不是费用账单。调用未经过平台日常任务计费链路，只在本实验记录用量。

## 校准、负对照与证据保留

- 初次 DSH 实模型尝试遇到测试网关错误：供应商非流式 `tool_calls` 自带 `index`，转 SSE 时重复传入该字段。固定夹具没有该字段，所以没有提前暴露。修复后重跑 DSH，两组均通过；前六次失败请求不计入 Harness 成败，但计入总用量。
- 适配层开发期间的加载配置、传输启动、SDK 响应类型及 `stat()` 返回值问题已逐项修正。最终完整回归单独运行；开发中间结果不作为正式证据。
- 共享服务的五项契约测试通过，包括“换 action ID 确实会新建第二任务”的负对照。防重复来自稳定动作身份和领域服务回执，并非 Harness 自动保证。
- 共归档 19 个有效运行用例，逐项检查 93 项，16 个用例全通过；其余三个正是原 SDK 的恢复/steer 差异。不能把这 19 个异质用例换算成框架成功率。
- [元数据](../../experiments/canvas-agent-bench/results/2026-09-23/metadata.json)保存版本、构建哈希和总用量；每例保留请求/响应、工具审计、快照及事件。仅含合成内容，无生产密钥。

## 下一步边界

进入实际画布原型前仍需：将合成工具接到 Elren 的真实命令层；服务端画布版本与前端同步；用户/项目鉴权；平台任务与 Agent 动作的持久映射；单独取消；真实媒体上下文；浏览器验收。现有生产任务的跨 Agent 重试幂等并未因此完成。

仍待验证：多模态输入、压缩后重新读取原图、长会话、真实生成任务恢复、多个用户/项目并发、进程资源上限、工具超时/供应商限流、Codex Harness。当前样本不能支撑全局“最优框架”的结论。

复跑步骤见 [实验 README](../../experiments/canvas-agent-bench/README.md)。本轮没有变更产品前后端、现有服务配置、用户画布或 Siran 工作树。

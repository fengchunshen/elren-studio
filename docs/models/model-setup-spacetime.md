# SpacetimeAI · GPT Image 2.5 接入

## 当前模型和创作端展示

| 模型 ID | 显示名称 | 特点标签 | 用途说明 |
| --- | --- | --- | --- |
| `gpt-image-2.5-flare` | GPT Image 2.5 Flare | 快速生成 | 适合日常创作，快速生成高质量图片。 |
| `gpt-image-2.5-sunburst` | GPT Image 2.5 Sunburst | 精细编辑 | 适合参考图精修，注重修改准确性。 |
| `gpt-image-2` | GPT Image 2 | 通用生图 | 适合通用图片创作与参考图编辑。 |

两者是 OpenAI 官方模型，定位依据：[Flare](https://developers.openai.com/api/docs/models/gpt-image-2.5-flare)、[Sunburst](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst)。标签表达选型定位，不构成每次请求的速度或质量保证。

特点标签和用途说明通过后台 `config.display_tags`、`config.display_description` 配置。创作端只读取这两个明确的公开字段，不接收渠道、密钥或配置 JSON。模型菜单和已选入口均显示主要中文特点。

## 渠道及实际限制

### 参数范围复核（2026-09-15）

- GPT Image 2.5 本身并非只有自动规格。当前 [OpenAI 图像文档](https://developers.openai.com/api/docs/guides/image-generation#customize-image-output) 列明尺寸、质量、数量、格式、压缩和背景参数；Flare／Sunburst 的质量包括 `low`、`medium`、`high`、`xhigh`、`max`、`auto`。
- 当前产品显示“自动规格”的直接原因是本项目预设将 `size`、`quality` 固定为隐藏的 `auto`，并将 `n` 限为 1；这描述的是当前接入配置，不应被表述为 GPT Image 模型完整能力。
- 已保存实测：Flare 请求 `size=1024x1024`、`quality=low`，响应元信息为 `size=1145x1374`、`quality=auto`、`model=gpt-image-2-codex`。这一证据说明该次请求参数未按预期返回，不能单独证明此渠道所有手动参数永远不受支持。
- 当前渠道“使用教程”的图像章节同样给出 `size`、`quality`、`n` 示例，但示例使用 `gpt-image-2`，未列清 Flare／Sunburst 的支持矩阵；它还提示额外的格式、background 等参数可能被拦截。因此不能直接把 OpenAI 的完整参数列表作为该渠道已验收能力开放。
- 用户随后明确回复“开始”，批准一次独立的 `gpt-image-2.5-flare`、`1536x1024`、`medium`、单张参数验证。该次调用在 125.72 秒后返回 HTTP 524，无图片及质量元信息，结果为“验证未完成”，不是“参数不支持”。没有重试，未据此修改已发布参数或价格。证据保存在被忽略的 `server/data/spacetime-parameter-verification-20260915/request.json` 与 `summary.json`；无输出时 `size_honored` 记为 null。之前受限环境的 `ConnectError` 同样不能作为渠道不支持参数的证据。

- 地址：`https://spacetimeai.cc`，凭据引用：`ELREN_PROVIDER_SPACETIMEAI`。实际密钥只保存在被忽略且权限为 `0600` 的 `server/.env.providers`。
- 适配器：`openai_image_edit`，无参考图时转至 `POST /v1/images/generations`，有参考图时使用 `POST /v1/images/edits` multipart；当前最多 4 张参考图，单次输出 1 张。
- 此渠道启用 HTTP/2 和平台文档指定的 User-Agent。HTTP/1.1 的两次测试出现返回中断；HTTP/2 已取得图片。保留现有其他渠道的默认传输。
- **平台返回元信息与请求不一致**：指定 Flare 或 Sunburst，返回的 `model` 均为 `gpt-image-2-codex`。仅凭这个统一字段无法确认其内部是否分别路由到对应官方版本，后台保留核对记录。
- 请求 `1024x1024`、`low` 后，平台实际返回自动尺寸及 `quality=auto`。因此当前仅开放 `size=auto`、`quality=auto`，这些固定参数不作为 C 端可选控件，菜单标注“自动规格”。不向客户承诺固定输出尺寸或画质档位。
- 旧裸名 `gpt-image-2.5` 已实测返回 `404 model_not_found`，旧草稿保持未开放，不再提供其预设。

## 超时任务状态修复（2026-09-15）

截图中的“上游状态查询暂不可用，后台继续核对”原先没有区分恢复能力。实际 524 响应没有可查询任务 ID，因此旧单不能自动找回图片。

- API 根据原始 Attempt 和接口配置返回恢复方式：`poll`（查询已有任务）、`persist`（处理已保存响应）、`manual`（人工核对）。旧记录在读取时获得正确说明，保留原始错误证据与费用状态。
- Worker 与前端共用这一判定。无 ID、无可恢复响应的任务不重发请求；前端停止无效轮询，画布显示“结果待人工核对”，使用记录显示“待人工核对／待核算”。
- 人工核对任务不永久占用运行并发槽，也不持续堵在调度队列最前面；管理员补充真实任务 ID 时可重新进入已有任务查询流程。原任务和费用仍保持未知，未自动确认失败、入账或重复生成。
- 已在普通用户 Chrome 画布及使用记录验证。成功任务保留图片与 0.201 元费用；超时任务保留历史证据，不用成功任务结果冒充恢复。
- 供应商源站的同步请求超时仍存在。需要供应商补回具体请求结果或提供可靠的异步提交、状态查询接口，才能完成丢失结果的恢复；本次没有发出新的付费测试请求。

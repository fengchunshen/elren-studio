# 对话操作画布

2026-09-23：平台模式已接入第一版 DSH 画布助手。入口是画布右下角的圆形 Elren 小球，关闭面板后会恢复。本地直连模式继续使用原有普通对话。

## 当前可以做什么

- 读取当前项目的节点、选择顺序、版本、引用关系与真实可用模型。
- 输入区“从画布添加”可点选节点作为本条消息引用；再次点选或点击 × 移除，退出点选保留草稿引用。引用随消息保存，优先于之后变化的临时选区，不创建节点、连线或生成任务。
- 助手回复渲染标题、列表、强调、表格与代码块，清理危险 HTML；外层 Markdown 围栏和双重转义的强调标记按展示内容处理，代码原文保留。
- 创建或修改文字、图片生成、视频生成节点，设置标题、内容、提示词与规格，连接已有节点作为参考。
- 先读取制作方法库，再用结构化 `apply_workflow` 创建有分组、有连线的流程，包括图片/视频分镜与剪辑时间线。批内 key 支持前向引用；视频分镜按稳定镜头身份绑定图片。`inspect_workflow` 区分结构错误和待补素材。公共模板里的“短剧制作 · 剧本到剪辑”复用同一原创蓝图；方法来源和验收范围见 [参考产品制作方法](./research/reference-workflow-methodology-2026-09-29.md)。
- 写剧本时助手直接创作正文并写入文字节点；`generate_node` 仍只执行普通图片/视频节点。分镜逐镜生成与画面/视频确认使用已有分镜界面。
- 每批画布修改整体校验后应用，进入现有撤销记录；节点被手动修改后，旧版本命令会拒绝覆盖。
- 对话中请求图片或视频生成，显示“开始生成 / 取消”。点击确认后通过现有任务、素材上传和计费服务提交；查询不会重新生成。
- 停止后续助手操作，刷新后恢复对话和画布。停止助手不会声称撤回供应商已接受的生成任务。
- 对话按用户和项目隔离。管理员的渠道、Key 和成本配置不进入创作 UI 或 Node 子进程。

示例：

```text
创建一个图生视频工作流：先创建银色水杯产品图，再连接到展示视频，写好提示词，只搭建，不生成。
只把视频节点改名为“水杯特写”，镜头改成缓慢推近，图片和连线不动。
为图片节点生成一张图片。
刚才的生成任务现在是什么状态？只查询。
```

## 存储与执行边界

当前画布仍保存在浏览器。助手在服务端规划，通过持久化操作记录请求对应浏览器执行画布命令，得到真实保存结果后再继续。关闭侧栏不等于停止；关闭项目页面后，依赖画布的步骤等待该页面重新连接，最长五分钟，超时明确失败。当前不承诺页面离线后仍能独立修改画布，也不是跨设备画布协作。

服务端会话、消息和操作回执分别保存在 `canvas_agent_sessions`、`canvas_agent_actions`；DSH 上下文日志保存在素材目录同级的 `agents/<会话ID>/home`。备份数据库和现有素材卷时一并保留这些日志。

画布命令通过确定性新节点 ID、节点版本、节点动作标记以及项目本地回执处理重放。生成使用 `canvas-agent-<操作ID>` 作为后端幂等标识，提交成功但客户端丢失响应时找回同一 Task。重复确认不会提交第二个生成任务。

当前对话绑定一个画布客户端；其他客户端可查看历史，不会抢执行中的操作。同一浏览器多标签通过 Web Locks 串行执行。服务端会话租约阻止不同 API 实例同时运行同一对话；当前建议使用单 API worker，不包含跨实例流量路由与完整高可用调度。

DSH 开放七个领域工具：`read_canvas`、`read_workflow_library`、`apply_canvas_patch`、`apply_workflow`、`inspect_workflow`、`generate_node`、`get_generation`。不开放 Shell、任意文件读写、网址访问或插件自安装。提示词中的资料是数据，工具参数还需经过 Pydantic 与前端命令校验。

## 安装和启动

平台助手需要 Node.js 24+；普通前端本地模式仍可使用原基线。DSH npm 家族统一固定为 `0.1.6-alpha.1`，lockfile 随代码交付，避免 npm 自动混入不同预发布版本。运行时独立于 Siran，不读取其工作目录、凭据或插件配置。

已有开发环境只需：

```bash
npm ci --prefix server/agent-runtime --ignore-scripts
python3 dev.py migrate
```

`npm run dev:setup` 已加入按 lockfile 哈希检查和安装该运行时的步骤。使用现有 `npm run dev:all` 或三个源码开发服务；不要为验收另开相同端口。

迁移 `0005` 只新增助手会话、操作记录表和索引，不改写现有项目数据。没有安装运行时或不可用模型时，界面明确显示助手不可用。

后端 Dockerfile 增加独立 Node 24/DSH 构建阶段。应用仍以非 root 用户运行，日志位于已有 `platform_assets` 卷的 `agents` 子目录。无需把用户的 Siran checkout 放入镜像。前端镜像同时包含现有品牌启动脚本。

更新运行时插件文件后需重启 API，不能仅依赖前端 HMR；修改 Python 服务由现有开发重载处理。服务退出会关闭其 DSH 子进程，未完成会话可通过新的用户消息恢复。

## 模型、用量与错误诊断

助手读取管理员开放的 `text.generate/openai_chat` 模型。本轮实际使用现有 DeepSeek Flash；供应商密钥只由 Python 读取。每次模型请求记录平台 Task、Attempt 和原始供应商证据，再使用现有用量归一化、成本/售价快照入账。媒体任务仍由原 Worker 处理。

一轮最多 32 次模型调用，每次最多 8192 输出 Token，以容纳含镜头与连线的原子工作流对象；单进程最多保留 8 个助手运行实例，空闲实例回收。对于提交结果未知的文字请求，用量保持待核对，不伪造零费用。

本机曾出现两处真实接入问题，均已修复并增加测试：

1. Clash Fake-IP 将官方 `api.deepseek.com` 解析到 `198.18.0.0/15`，被预检判为内网。助手仅为这个精确的 HTTPS/443 官方域名兼容该虚拟地址范围；仍校验 TLS 且不跟随重定向，其他内网地址和域名不放行，不设置 `ALLOW_PRIVATE_PROVIDERS`。正常的公共 DNS 继续沿用原校验。
2. `normalized_usage()` 返回 `(meters, raw)`，最初接入误把元组传入记账函数，导致模型返回后处理失败。现已正确解包，并先保存供应商证据，防止后续记账异常丢失诊断。

画布状态和生成状态来自实际操作回执，不用成功提示掩盖错误。普通用户只看到简短失败说明；服务端日志及管理任务证据用于诊断。

## 仍未验收或暂未开放

- 本轮未执行真实图片/视频供应商生成；确认后提交、幂等和权限由隔离测试验证，真实媒体生成效果与供应商行为不能据此宣称通过。
- 助手读取的是素材身份与文字元信息，没有直接视觉理解；不能声称已经看过图像细节。选择的 DeepSeek 模型目前也是文本接入。
- 2026-09-29已开放工作流中的分镜内容、稳定首帧绑定和时间线连接/布局，保留已有作品与裁切；仍不通过 Agent 执行分镜逐镜生成、时间线合片，或修改音频/3D、蒙版、删除节点、管理账户。既有手动能力继续保留。
- 尚无服务端权威画布快照、离线全流程创作、多人实时协作、长上下文压力测试或分布式调度验收。
- 新助手对话与原浏览器普通聊天历史分开存储；未迁移旧聊天记录。消息引用已保存节点 ID、名称、类型、版本及文字快照；缩略图仅用于当前浏览器预览，不把本地图片数据作为文字模型的视觉输入。尚未接入旧聊天的文件上传流程。
